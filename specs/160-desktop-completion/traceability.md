## Read the status correctly

| Label | Meaning |
| --- | --- |
| SOURCE | Mechanism exists in the current serving code; do not rebuild it merely because an old checklist is open. |
| FIXTURE | Exercised deterministic server/transport/model/target behavior. Real browser or native-constructor work is identified separately; it is not automatically real-model agency or installed-product proof. |
| HISTORICAL-NATIVE | A specific dated record reports actual native/model/installed behavior at its named version/commit. It is preserved, not carried forward to certify this candidate. |
| IMPLEMENTATION | A concrete required seam is absent/incomplete in the inspected serving path. |
| VERIFICATION | Code or historical evidence exists, but the required exact-candidate/platform/outcome proof is missing. |
| RISK | Source-supported consequence not reproduced here; not a demonstrated exploit, duplicate effect or unauthorized bill. |
| EXTERNAL / DECISION | A real identity, entitlement, native machine, external caller or product-policy decision must be supplied/settled. Uninspectable configuration is not automatically absent. |
| PARKED | Explicitly deferred or an unapproved expansion; not a dependency invented for basic desktop qualification. |

A consumer-visible failing fixture and a stale incidental assertion are different problems. A file named `green` is not a pass; check its actual result, timestamp, scope and candidate.
